# 测试策略与门禁（Murat）

## 何时用
需要测试策略、测试设计、发布前门禁或追溯时。

## 先读
- `bmad-output/prd.md`、`bmad-output/architecture.md`
- `bmad-output/index.md`（story 与其验收标准）

## 步骤
1. 按风险给 story/功能排测试优先级（高/中/低）。
2. 设计测试：单元/集成/端到端如何分工；每条验收标准对应到测试。
3. 落盘 `bmad-output/test-strategy.md`。
4. 给出门禁结论：PASS / CONCERNS / FAIL，并说明理由与缺口。

## 必须主动覆盖的非功能与安全维度（不依赖他人提示）

除 happy path 外，测试设计必须**主动**纳入以下维度并各落到具体用例：

- **冷启动 / 首次请求**：首个请求与稳态在计算量与代码路径上是否一致；涉及「不可区分」要求时，用**确定性计数 / 注入桩 / 状态快照**断言「首个请求 == 稳态」，禁止以墙钟耗时或基准阈值作通过标准。
- **环境配置异常边界**：缺失、越界（过短 / 过长 / 临界值两端）、类型非法各测一例；边界按**正确度量单位**定义（如按字节而非字符计长度），并断言错误 / 日志**不回显敏感值**。
- **安全负路径**：认证 / 授权失败一致性、防枚举（不同失败分支在状态码 / 响应体 / 计算量上不可区分）、令牌伪造 / 过期 / 算法混淆（如 alg 降级）/ 畸形输入等，逐条对应负路径用例。
- **启动期不变量**：关键前置（预热 / 缓存 / 密钥强度 / 依赖就绪）必须在对外服务**之前**就绪，违规即 fail-fast（进程非 0），不被拖到首个请求才暴露。

优先用**确定性断言**（调用计数、注入桩、状态快照）证明行为；对无法自动测试的残余风险显式记录理由与缓解 / 监控手段，不得以「人工看过」充当门禁证据。
