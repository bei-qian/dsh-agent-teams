# 测试策略与门禁（Argus）

## 何时用
需要测试策略、测试设计、发布前门禁或追溯时。

## 先读
- `bmad-output/prd.md`、`bmad-output/architecture.md`
- `bmad-output/index.md`（story 与其验收标准）

## 步骤
1. 按风险给 story/功能排测试优先级（高/中/低）。
2. 设计测试：单元/集成/端到端如何分工；每条验收标准对应到测试。
3. 落盘 `bmad-output/test-strategy.md`。
4. 给出门禁结论：PASS / CONCERNS / FAIL —— 用**发布前就绪清单**承载（见下），说明理由与缺口，未满足项显式列 open item。

## Token 纪律（TEA 侧）

总则见 `bmad-squad-protocol` 的「Token 纪律」；本节点出 TEA 独有的几条：

- **视觉 / E2E 证据唯一产出方是 TEA**：截图、录屏、端到端跑批证据由 TEA 统一产一次；DEV 不自建一套、Lead 不重复造。
- **证据摘要化**：回报只写**状态 + 关键断言 + 截图路径清单**，不把整份日志 / 整份 gate 报告贴进上下文；明细落 artifacts 文件，按需段读（规则 A + C）。
- **一次取证、多处引用**：同一份证据用路径引用，不重复整读；日志重定向到文件后只回传状态行 + 错误行 + 行号。
- **等待不轮询**：长跑 E2E / dev-server 用后台 job + 一次有界等待（`job_output` 带上限），不写轮询循环（规则 B）。

## 必须主动覆盖的非功能与安全维度

除 happy path 外，测试设计必须**主动**纳入安全与非功能维度并各落到具体用例：**确定性安全测试要求见 `cap-security-baseline`**（威胁建模驱动的认证 / 授权、防枚举、输入边界、启动期不变量、失败路径一致性等），本技能不重复逐条。

统一底线：优先用**确定性断言**（调用计数、注入桩、状态快照）证明行为；对无法自动测试的残余风险显式记录理由与缓解 / 监控手段，不得以「人工看过」充当门禁证据。并遵守**「弱化机制不得冒充保证」**：删测试、放宽断言、重试掩盖、弱隔离冒充隔离换来的「绿」不是通过，必须显式记为 open item。

### 布局 / 视觉类 AC 的两条硬要求

布局 / 视觉类 AC 若只做「肉眼看着变好」或单层读数，会**假绿**（把疑似改善当通过、把元素消失当优化）。两条硬要求缺一不可：

1. **逆向断言**：凡票面包含「收缩 / 压缩 / 降级 / 腾空间」类改动，AC 必须同时断言**未被要求删除的元素仍然可见**（例：`expect(el).toBeVisible()` 或 computed `display !== 'none'`），否则「变好了」可为「消失了」。
2. **溢出双层量 + 镜像基线**：判「无横向滚动」不得只量 `documentElement`——`body{overflow-x:overlay}` 会把 body 层平移吃掉、宽内容会把盒宽钉住，只量 `documentElement` 时该值可恒等成立。AC 必须同时给 `body.scrollWidth <= clientWidth` **与** `documentElement.scrollWidth <= clientWidth`，并声明测量环境**镜像**了全局 `min-width` / `overflow-x` 基线；只写单层即视为**判据不完整**。

## 发布前就绪清单（门禁）

门禁结论不是一句判定，而是**逐项就绪清单**：每项 = 已跑过的命令 + 证据（输出 / 文件路径）+ **生效阈值及其来源**。未满足项显式记为 `open item`，**不得静默 waiver**。整体判定仍取 PASS / CONCERNS / FAIL——存在 open item 至少 CONCERNS，关键项未满足即 FAIL。

**门禁阈值口径**：覆盖 / 证据强度等门槛**按风险分级可配置**（高/中/低风险门槛不同）；每项记录**生效阈值及其来源**（默认值 / 配置 / 覆盖）；**非法策略配置须显式拒绝报错**，不得静默回退默认值。

- [ ] `<验证项>`：命令 `<命令>` → 证据 `<退出码 / 输出摘要 / 证据路径>` + 生效阈值 `<阈值>` / 来源 `<默认值 | 配置 | 覆盖>`
- [ ] 高风险 AC 覆盖：要么有对应测试，要么在覆盖排除登记表写明具体理由（登记表随报告）
- [ ] 证据时效：实跑证据绑定所测版本 / 提交摘要（含被测材料 hash），材料变更后旧证据标 stale
- [ ] 弱化机制检查：无「删测试 / 放宽断言 / 重试掩盖 / 弱隔离冒充隔离」换来的绿；若有则记 open item 并说明
- [ ] 不可测 AC 显式处理：AC 标注可测/不可测；不可测项保留清单 + 具体理由，**默认 halt**，仅显式受控降级才 `skip-and-report` 并上报被跳过数量；完成前校验每个可测 AC 恰有一个可执行测试（细节见 `cap-testing-strategy` 的 `SKILL.md` 与 `references/test-design.md`）

## 缺陷登记与报告分层（A2，口径以 `cap-testing-strategy` 正文为准）

发现被测对象缺陷先登记为「待处置 finding」（**证据 + 拟改产物 + 严重度**），**不打断**本次测试主循环；收尾**成批拍板**处置（本 PR 修 / 另开 PR 移交 / 拒绝并记理由）并**成批一次验证**，不逐条 `fix-and-rerun`。报告分三层并显式写净改进（改前→改后数字，**抄录**实测、不重算）；无对象缺陷时写「**None found**」。
