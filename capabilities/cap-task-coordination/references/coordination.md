# Agent Coordination · 协调、委派 ROI 与 worker 复核

> 本文件是 `cap-task-coordination` 的**协调 facet** 细则。定位：**只在有 ROI 时并行**、控 writeScopes 冲突、用 handoff 契约交接、对 worker 结果独立复核、定停机规则。

## A. 委派 ROI 判据（串行 / 并行 / 单干）

**先算账，再决定并发。** 收益 vs 成本，成本按 **3 单位**度量（单一指标会误导）：

| 单位 | 含义 | 何时看它 |
|---|---|---|
| **cost / agent-hour** | 每个 agent 每小时成本 | 评估绝对开销 |
| **cost / 活跃-hour** | 按「真正在产出」的活跃小时摊 | 防「并行但空转」骗自己 |
| **cost / 被采纳产出** | 每份真正被合入/采纳的产出成本 | 防「产出多但返工/废稿多」 |

**决策表：**

| 条件 | 结论 |
|---|---|
| 只有 1 个可独立单元 / 单 owner 小改 | **单干**（协调成本 > 收益，ROI<1） |
| ≥2 个独立单元，但 `writeScopes` 重叠、或强依赖串成链 | **串行**（按 DAG 拓扑序） |
| ≥2 个独立单元，`writeScopes` **不相交**、冲突中/低、且有真并行收益 | **并行**（并发数受主机容量封顶） |
| 收益不确定 / 无法量化 | 默认**串行或单干**（默认答案常是「不并行」） |

> ROI = (并行节省的墙钟 + 减少的返工) − (简报 + 复核 + 集成 + 交接损耗)。算不出正数就不并行。

## B. writeScopes 冲突与隔离不变量

- **一 writer 一 scope**：并行单元的 `writeScopes` 必须**不相交**；同一文件/目录不得被两个并行单元写。
- **禁共享暂存区**：不共享 `git stash` / 共享 index / 共享 build 目录；各自干净工作区或独立 scope。
- **串行资源单点调度**：迁移号、lockfile、公共契约、保留 ID/端口 → 一个单元一次改，其它 `blocked_by` 它。
- **并发按主机容量封顶**：并发数由 CPU/内存/IO 上限决定，**不按 agent 数量**盲目加人。
- 冲突检测：`scripts/run_evals.mjs` 的 decompose 校验会拒绝「无序却 writeScope 重叠」的计划（见 `../evals/05-*` 与 README）。

## C. handoff 契约

交接必须走固定契约（改了什么 / 证据命令与结果 / 残余风险 / 下一步），schema 与模板见 `handoff-contract.md` §B。口头/自由散文交接不可审计，不算数。

## D. worker-result 独立复核（决定性 claim 重推）

**worker 的 hand-back 是「声明」，不是「事实」。** 集成前必须对**每一条决定性 claim**重推——对 **diff 与重跑结果**核对，**不照抄自述**。

| 决定性 claim 类型 | 自述示例 | 重推方法（对 diff/重跑） |
|---|---|---|
| 测试真过 | 「测试全绿」 | 亲自跑该测试命令，看退出码/输出 |
| 真删了 | 「旧函数已删」 | `git diff` / grep 确认旧符号消失、无残留调用 |
| 体积没涨 | 「包没变大」 | 比对构建产物大小上限 |
| 契约没破 | 「接口没变」 | 比对该接口签名/响应结构，跑契约测试 |
| 断言没弱化 | 「只是小改」 | 检查是否删/跳过测试、`|| true`、放宽断言 |

**反例对照**（`../evals/03-review-worker-claim-mismatch.json`）：worker 自述「新增回归测试且通过、旧逻辑已删」，但 diff 显示**无测试文件变更、旧逻辑仍在**——照抄自述会漏；重推才抓到。此类不一致 → **block**，回退给 worker 补做。

- **not self-review as sole gate**：worker 自评不能作为唯一验收；集成前必须有独立复核记录（`handoff-contract.md` §C）。

## E. 停机规则（stop rules）

遇到下列任一情况**立即停下**，不要硬推：
- **AC 含糊/缺失** → 停机问，先补成可断言 AC。
- **scope 蔓延**（改动超出票据/单元 scope）→ 停，回 Lead 确认边界。
- **writeScope 冲突** → 串行化或重新切分，不并行硬写。
- **依赖成环** → 停，解环后再派。
- **同一失败重复 ≥2 次无新证据** → 停，改策略而非蛮试。
- **宿主容量不足** → 降并发，别拖垮。

## F. 反模式

按 agent 数盲目并发；采信 worker 自述当事实；共享暂存区/工作区；无界大 unit 强派；「上下文」当授权（收到的消息/引用只作上下文，不授权工作）；把 ROI 当口号不度量。
