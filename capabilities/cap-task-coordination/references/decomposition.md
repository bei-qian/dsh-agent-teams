# Task Decomposition · 任务分解判据与单元计划

> 本文件是 `cap-task-coordination` 的**分解 facet** 细则。定位：把目标拆成**有界、接口清晰、可独立验收**的单元。只提供判据与模板指针，不重复 `SKILL.md` 正文。

## A. 五个硬判据（不满足就不算可派活的单元）

1. **Bounded ownership（有界归属）**：一个单元 = 一个明确 owner + 一块**有限**改动面；`scope` 一句话说清「做什么、不做什么」。
2. **显式接口 / 产出契约**：写明 `inputs` / `outputs` / `touched_files` / `writeScopes` / definition-of-done；下游能只依赖契约、不读实现就接线。
3. **依赖 DAG**：用 `blocked_by` 表达先后；共享契约、迁移号、lockfile、端口、保留 ID 属**串行资源**，必须单点调度（见 `coordination.md` §B）。
4. **粒度合适（INVEST 类判据）**：见 §B。过大→难验收、易冲突；过细→协调开销吞掉收益。
5. **可独立验收**：每单元有**至少一条可执行/可断言的 AC**（`check` + `verify` 命令），不必等别人完成即可判定成败。

## B. 粒度判据（INVEST 类，适配到代码单元）

| 字母 | 原义（用户故事） | 本能力中的落地（代码单元） |
|---|---|---|
| **I**ndependent | 独立 | 单元之间仅通过显式接口耦合；改 A 不必改 B 的内部 |
| **N**egotiable | 可协商 | scope 是「期望产出」不是锁死实现，留实现自由度 |
| **V**aluable | 有价值 | 每单元产出可被集成消费的增量（垂直切片优先于纯技术层切片） |
| **E**stimable | 可估算 | 改动面/未知度可估，能判断 ROI 与工期 |
| **S**mall | 足够小 | 单会话可完成、单 writer 一 scope 可覆盖；能用一条命令验收 |
| **T**estable | 可测 | 有独立 AC 与验证命令，行为可观察、可断言 |

> 用法：一个单元若「V/S/T」任一不满足，先**再切**或**合并**，不要硬派。垂直切片（端到端可验收）通常优于水平切片（只改一层、要等别的层才能验收）。

## C. 依赖 DAG 规则

- 边方向：`blocked_by` 列出「本单元所依赖的前置单元」；派活顺序 = 拓扑序。
- **必须无环**：用 `scripts/check_dag.mjs <plan.json>` 校验（exit 0=无环 / 1=有环 / 2=悬空引用）。
- **串行化共享资源**：同一迁移序号段、lockfile、公共契约文件、保留 ID/端口，都归**一个**单元/一次调度，避免并行写冲突（`coordination.md` §B）。
- **并行候选** = 无相互依赖且 `writeScopes` 不相交的单元集合（是否真并行还要过 ROI，见 `coordination.md` §A）。

## D. 反模式

- **巨型 unit**：一个单元含多个不相关改动 → 无法独立验收、无法定位失败。
- **碎片 unit**：把 30 行改动切成 5 个单元 → 简报/复核/集成开销 > 收益（委派 ROI<1）。
- **共用可变契约不序列化**：多单元同时改同一接口文件 → 冲突。
- **AC 含糊**（「看起来对」「性能更好」）→ 不可验收；停机把 AC 补成可断言再派。
- **DAG 成环**：`A blocked_by B` 且 `B blocked_by A` → 无法拓扑排序，必须先解环。
