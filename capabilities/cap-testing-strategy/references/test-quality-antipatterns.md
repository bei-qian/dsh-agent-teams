## 1. TDD 纵向切片最小样例（一个 feature，一片一片来）

诉求：`applyPercentageDiscount(priceCents, percent)` 给出折后价（整数分；`percent` 语义 clamp 到 `[0,100]`，即负值当 0、超 100 当 100）。

一个纵向切片的 TDD 节奏（每轮：**红 → 绿 → 重构**）：

1. **红**：先写第一条会失败的行为测试 `impl(1000, 0) === 1000`（实现还没有，红）。
2. **绿**：写最小实现 `return priceCents`（只让这一条过）。
3. 下一片：**红** `impl(1000, 100) === 0` → **绿** 补上按比例计算。
4. 再一片：**红** `impl(1000, -10) === 1000`（负百分应 clamp、不得加价）→ **绿** 补 clamp。
5. 绿之后**重构**（抽常量、改名），测试全程保持绿。

> 反例（横向切片）：先把 10 条测试全写完，再写实现——你锁死了还没想清的测试结构，且测到的是想象中的形状，不是真实行为。

## 2. 证伪证明：注入 1 处缺陷，行为测试变红（确定性）

承上，正确实现 `fixed` 的关键是 `Math.min(100, Math.max(0, percent))`（clamp）；注入缺陷 `buggy` 去掉 clamp（负百分会加价、超 100 会变负），并改坏边界舍入：

- `fixed` 上行为测试（含 `impl(1000,-10)===1000`、`impl(1000,150)===0` 等边界 / 负路径）**全绿**；
- `buggy` 上同组行为测试**至少 1 条变红**（缺陷被抓住）；
- 「浅测」（只断言「返回数字 / 有限 / 不抛」）在 `buggy` 上**仍全绿**（数量 / 浅测抓不住缺陷）。

**可执行证据（零依赖，确定性断言：改坏→红、改好→绿）**：

```
node scripts/falsification_demo.mjs   # exit 0 = 证伪性成立：好测试能红，浅测再多也不红
```

## 3. 三类反模式的快速判定（定义见 `SKILL.md`，此处只给判定口诀）

- **实现耦合**：重构后行为没变、测试却红了 → 把断言上移到公共 seam。
- **同义反复**：实现写错也不会红（期望值由实现现算 / 常量自证）→ 换独立真相源。
- **横向切片**：先写一堆测试再写实现、测的是想象形状 → 改纵向切片（一条测试 → 一条实现 → 重复）。

> 负路径 / 边界：反模式清单不等于「禁止 mock」——真实接缝与外部不可控依赖仍需测试替身，判据是「测行为还是测实现」；何时不值得先写测试见 `bmad-build` 的 TDD 循环纪律。
